# Space Werewolf v2.0.0 Update Announcement

## Update Overview

v2.0.0 is a milestone release that moves the game from "same-screen turn-based play" to "local network real-time multiplayer". This update adds a complete multiplayer lobby, room system and position synchronization, fixes the crash issues that had long plagued online testing, and rebalances the cooldowns for multiplayer mode.

Single-player mode keeps its original turn-based gameplay and is **completely unchanged**.

---

## New Features

### 🌐 LAN Multiplayer

**Mode Selection Lobby:**
- The game now starts with a mode selection screen offering "Single Player", "Create Room" and "Join Room"
- Hosts can customize their name and see the local LAN IP to share with friends
- Guests enter the host's IP and their own name to connect

**Room Server:**
- The host listens on port `8888` using a JSON line-delimited protocol (each message ends with `\n`)
- Clients report their name on connect; the host detects duplicates and auto-renames (e.g. `Player2(1)`)
- Player count and player list are broadcast in real time; the host can start once the minimum is met

**Role Assignment:**
- Roles are randomly assigned by the host and distributed to each client via command-line arguments (base64-encoded JSON)
- Each client only sees its own role, preventing identity leaks during local viewing
- Role assignment backup files are cleaned automatically to avoid stale data being reused

### 📍 Position Synchronization

- The host runs a `12346` sync server inside the game process, alive until disconnect
- The full room state (`room_state`) is broadcast every 500ms: positions, alive status, task progress, sabotage state, bomb info, body locations, etc.
- Position updates are relayed to other players but never echoed back to the sender; the host itself joins via a loopback connection
- The sync client includes reconnect logic, so it can still connect if the host's server starts a little later

### 🧩 Detached Process Launch

Previously the game process was launched directly by the lobby and inherited its console/pipe handles, so it was killed as soon as the lobby exited. v2.0.0 launches it fully detached:

- Game `stdout`/`stderr` are redirected to dedicated log files (`game_host_*.log`, `game_client_*.log`)
- Windows uses `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`
- Linux / WSL uses `start_new_session`
- The lobby exiting no longer kills the game process or triggers `SIGPIPE`

### 🛡️ Crash Logging

- Global capture of unhandled exceptions (`sys.excepthook`, `threading.excepthook`, Tk callback exceptions)
- `faulthandler` enabled so hard crashes (segfaults) also produce a Python stack trace
- Each run produces `crash_<pid>.log`, ending with a normal-exit marker to distinguish crashes from clean exits

## Bug Fixes

### Multiplayer Crashes (core of this release)

The crash had three independent causes stacked together, all now fixed:

1. **Process inheriting lobby handles** — the game process received a close event when the lobby exited; fixed with fully detached launch.
2. **Sync server dying with the lobby** — clients got `WinError 10061` on port `12346`; the sync server now lives inside the host's game process, with an idempotency flag to avoid double-binding (`Errno 98`).
3. **Windows Chinese-locale encoding crash** — characters such as `✓` and `✗` cannot be encoded in GBK, so `print` raised `UnicodeEncodeError`, which killed the server/client message threads (symptoms: "host cannot see new players", "client stuck in the room screen without launching the game"). `stdout`/`stderr` now tolerate encoding failures, and game child processes output UTF-8.

### Windows Role Entry Launch Failure

`crewmate_entry.py` / `impostor_entry.py` used to replace the process with `os.execv`. On Windows, `os.execv` does not quote arguments containing spaces when rebuilding the command line, so with a project path containing a double space the script path was truncated and the game process never started (symptom: "window disappears right after the lobby closes"). They now use `runpy` to execute `main_gui.py` as `__main__` in the same process, without rebuilding any command line.

### Other Fixes

- Impostor victory check now requires a player to have been eliminated, preventing a 1v1 instant win at 2 players
- Player names are now passed as base64-encoded JSON, so names containing commas or spaces work correctly
- The host now reclaims a player's slot when a client disconnects, preventing "ghost players" from occupying the room
- Fixed a missing-`()` bug on `title_label.pack`
- Removed the overridden legacy discussion/vote logic (~145 lines) and unreachable code
- Cleaned dead code and duplicate imports in `game.py`, `multiplayer.py`, `tasks.py`, `haikediannao.py`

## Technical Improvements

- Network layer uses a unified JSON line-delimited protocol for easier capture and debugging
- Room state reads/writes are lock-protected; broadcast and relay paths are separated to avoid thread races
- All launch commands use `python -u` with dedicated log files, eliminating log loss
- New headless protocol self-test: no GUI, no X11 dependency, full protocol regression in seconds
